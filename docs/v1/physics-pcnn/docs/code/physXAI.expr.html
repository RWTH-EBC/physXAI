physXAI.expr package

physXAI expression language: physical arithmetic and trainable blocks in one graph.

>>> from physXAI import expr as px
>>> v = px.Vars()
>>> architecture = px.Linear([v.V_flow, v.V_flow * (v.T_sup - v.T), v.T])

See physXAI.expr.core for details.

Submodules

physXAI.expr.blocks module

Trainable building blocks of modular models.

A block maps a list of input expressions to one output. Blocks normalize their inputs themselves (with statistics of the training data, if the inputs are data only), so arithmetic outside of blocks can work on raw physical values.

physXAI.expr.core module

Core of the physXAI expression language.

An expression is an immutable node of a directed acyclic graph. It can be evaluated by three backends:

  • evaluate(values): NumPy / pandas, e.g. to create a data column in the preprocessing.

  • to_keras(ctx): Keras layers, i.e. the expression becomes part of the model. Only layers

    the CasADi export of AgentLib-MPC supports are used.

  • to_casadi(syms): CasADi, e.g. for constrained regressions.

Example

>>> from physXAI import expr as px
>>> v = px.Vars()
>>> heat_flow = v.mDot * (v.T_in - v.T)            # raw physical arithmetic
>>> model_output = px.Linear([v.load, heat_flow])  # trainable block
>>> model_output.free_vars()
['load', 'mDot', 'T_in', 'T']

Variables are data columns. v.T.lag(1) refers to the column ‘T_lag1’, which the preprocessing derives automatically. Arithmetic works on raw (not normalized) values; trainable blocks normalize their inputs themselves.

physXAI.expr.serialization module

Json serialization of expression graphs.

A graph is stored as a list of nodes in topological order, every node referring to its children by id. Shared sub-graphs (e.g. a parameter used twice) stay shared after loading.

{“nodes”: [{“id”: “n0”, “type”: “Var”, “name”: null, “params”: {“column”: “T”}, “inputs”: []}, …],

“outputs”: [“n3”]}
