Getting started

physXAI trains data driven models of building energy systems for model predictive control (MPC), in particular for AgentLib-MPC. A typical workflow:

  1. Preprocessing loads a csv file, derives lags and changes, splits the data without leakage and returns training data.

  2. A model is trained and evaluated: single step metrics and, for models applied recursively in an MPC, the error over the prediction horizon.

  3. A run directory stores configs, metrics, the model and a report, so runs can be reproduced and compared, and AgentLib-MPC can load the model.

Installation

physXAI runs on Python 3.11, 3.12 and 3.13 on Linux and Windows. Python 3.14 follows with TensorFlow 2.22, the first TensorFlow release with wheels for it (only a release candidate so far).

pip install .                    # user
pip install . -c constraints.txt # user, with the versions physXAI was tested with (reproducible environment)
pip install .[gpu]               # user, training on a GPU (Linux or WSL2, see below)
pip install -e .[dev,agentlib]   # developer: tests, linting, AgentLib-MPC contract tests
pip install -e .[docs]           # documentation: sphinx-apidoc -M -o docs/source/code physXAI && sphinx-build -b html docs/source docs_output

The dependencies have upper bounds on their next major versions. constraints.txt pins all (also transitive) packages to the combination tested for the release.

GPU

physXAI needs no changes to train on a GPU: TensorFlow places the operations on a GPU if it finds one. Only the installation differs:

  • Linux: pip install .[gpu] installs TensorFlow with CUDA (tensorflow[and-cuda]), an NVIDIA driver is needed. python -c "import tensorflow as tf; print(tf.config.list_physical_devices('GPU'))" shows the GPUs found.

  • Windows: TensorFlow >= 2.11 has no GPU support on native Windows (it prints a warning and uses the CPU). Use WSL2 with the Linux installation.

The small networks of building models often train about as fast on a CPU; a GPU pays off for large data sets, recurrent models and many repeated trainings (repeat_training).

A first model

The air temperature of a room is predicted as change per time step, Change(T) = T(t+1) - T(t). A model predicting a change is applied recursively in the MPC: the predicted temperature becomes the input of the next step.

from physXAI import expr as px
from physXAI.io import Run
from physXAI.models import LinearRegressionModel
from physXAI.preprocessing.preprocessing import PreprocessingSingleStep

run = Run("results", "TAir", overwrite=True)

prep = PreprocessingSingleStep(
    inputs=["weaSta_reaWeaTDryBul_y", "oveHeaPumY_u", "oveHeaPumY_u_lag1", "reaTZon_y"],
    output=px.Change("reaTZon_y"),   # or the string 'Change(reaTZon_y)'
    time_index_col="time",
    eval_horizon="12h",              # also evaluate the recursive prediction over 12 h
)
td = prep.pipeline("data/bestest_hydronic_heat_pump/pid_data.csv")

model = LinearRegressionModel()
model.pipeline(td)                   # train and evaluate

run.save("model", prep, model, td)   # configs, metrics, model and report

run.save writes into results/TAir/:

File

Content

model_preprocessing.json

config of the preprocessing (PreprocessingData.from_config)

model_model.json

config of the model (AbstractModel.model_from_config)

model_training_data.json

metrics per output and split, errors over the horizon, training time and history

model.joblib / model.keras

the trained model

model.html

Lagged inputs such as oveHeaPumY_u_lag1 and the output Change(reaTZon_y) are derived from the data automatically. The examples continue this tutorial step by step.

Run directories and logging

Run(base_path, name, overwrite=False) is an explicit directory. Paths are absolute or relative to the current working directory, there are no interactive prompts and no files are deleted. Without overwrite=True, existing files are not overwritten (FileExistsError).

physXAI logs with the standard logging module (logger "physXAI"). By default metrics and the training progress are shown:

from physXAI import set_log_level

set_log_level("warning")   # only warnings, no keras progress bars

If the application configures logging itself (e.g. logging.basicConfig), physXAI messages are passed on to it instead of being printed.

Reproducibility

Every random choice (split, weights, batches, k-means centers) is seeded. physXAI.set_seed(42) sets one global seed for Python, NumPy and Keras, which is the default of random_state (preprocessing) and random_seed (models). Without a seed, every object draws one and stores it in its config, so every run can be reproduced from its saved configs. The saved configs also record the versions of Python and of the main packages (environment).

On a CPU, a seeded run is reproduced exactly. On a GPU, some TensorFlow kernels are not deterministic, so two runs with the same seed differ slightly. physXAI.set_seed(42, deterministic=True) enables the deterministic kernels of TensorFlow: runs on a GPU are reproduced exactly, the training is slower, and it stays enabled for the rest of the process.
