physXAI.evaluation.comparison module

Comparison of several models, each trained several times.

A single training run says little about a model: the split of the data and the initialization of the weights change the errors, often more than the difference between two models. repeat_training trains a model with several seeds and saves every run with Run.save. ModelComparison loads the saved runs (or takes training data in memory) and compares the distributions of the errors:

  • the single step metrics per output (RMSE, MAE, R2, bias),

  • the errors over the prediction horizon (recursive single step models and RNNs), on a common horizon,

  • plots of the distributions (box plots over the runs, median and band over the horizon).

Example

>>> run = Run("results", "TAir_compare", overwrite=True)
>>> repeat_training(file_path, prep, LinearRegressionModel(), seeds=5, run=run, name="linreg")
>>> repeat_training(file_path, prep, ClassicalANNModel(epochs=50), seeds=5, run=run, name="ann")
>>> comparison = ModelComparison.load(run.path)  # one model per sub directory
>>> comparison.summary()
>>> comparison.paired("linreg")  # run by run on the same splits: differences, confidence interval, p-value
>>> comparison.save(run, baseline="linreg")  # comparison.html and csv files

With the same seeds and the same split settings, all models use the same splits of the data, so their runs can be compared in pairs (paired), which removes the spread caused by the split.

classmethod load(paths, name=None)[source]

Loads saved runs: every file *training_data.json is one run, with the configs next to it.

Supported are runs written by Run.save / save_for_agentlib ({name}_training_data.json) and by the Logger of physXAI < 1.0 (training_data.json, model_config.json, preprocessing_config.json).

A model is a directory holding its runs, e.g. results/cmnn/<run>/... with any number of run directories named arbitrarily (results/cmnn/a1b2c3/, results/cmnn/x9y8z7/, …):

  • load('results'): every sub directory of results is a model (cmnn, ann, …),

  • load(['results/cmnn', 'other/ann']): every given directory is a model, named after it,

  • load({'CMNN': 'results/cmnn'}): every given directory is a model with the given label.

Runs are named after their directory below the model directory. If a run directory holds several models (e.g. T_training_data.json and P_training_data.json of AgentLib-MPC), they become separate models (cmnn/T, cmnn/P), unless name selects one of them. Files that cannot be read are skipped with a warning.

Parameters:

  • paths (str | Path | Iterable[str | Path] | Mapping[str, str | Path]) – The model directories, see above.

  • name (str | None) – Only load the files {name}_training_data.json of every run directory.

Raises:

FileNotFoundError – If a model directory holds no runs.

Return type:

paired(baseline, models=None, split='test', horizon=None, by='auto', confidence=0.95)[source]

Paired comparison of models with a baseline: the scores (see scores) are compared run by run on the same split of the data, so the spread caused by the split cancels out. Two models whose distributions overlap in summary can still differ clearly, if one of them is better on (almost) every split.

Runs are paired by the seed of their split (by='split_seed', the random_state of the preprocessing) or by their name (by='run', e.g. ‘seed_0’ of repeat_training). ‘auto’ takes the split seed if it identifies the runs of both models, else the name. The same seed gives the same split only with the same split settings: the block length depends on the window length (horizon, warmup) and on the size of the data. Every pair is therefore checked with the fingerprint of the split (same_data, saved with physXAI >= 1.0). Single step and recurrent models on the same split can still be evaluated on different windows (warmup inside the split).

Differences are model - baseline. RMSE and the absolute bias are better when lower, R2 when higher.

Parameters:

  • baseline (str) – Label of the reference model.

  • models (str | Iterable[str] | None) – Models to compare with the baseline. Defaults to all others.

  • split (str) – ‘train’, ‘val’ or ‘test’.

  • horizon (float | None) – End of the compared horizon (see scores).

  • by (str) – ‘auto’, ‘split_seed’ or ‘run’.

  • confidence (float) – Level of the confidence interval of the mean difference.

Returns:

One row per (score, model) with the number of pairs, the medians of the baseline and the model, the mean_difference with its confidence interval (ci_low, ci_high, Student t), the median_difference, the share of pairs in which the model is better, the p_value of the two-sided Wilcoxon signed rank test (needs at least 6 pairs to reach 0.05) and the share of pairs on the same_data (NaN if unknown).

Return type:

pd.DataFrame

physXAI.evaluation.rollout module

Recursive (multi step) prediction with single step models.

A single step model predicts the next value (or the change) of a feature it also gets as input. In an MPC it is applied recursively over the horizon: the prediction of step t becomes the input of step t+1. This module performs exactly this rollout on windows of the measured data:

  • The recursive feature (e.g. ‘T’ for an output ‘Change(T)’) and its lags (‘T_lag1’, …) are taken from the predicted trajectory, all other inputs from the data (they are known to the MPC).

  • Derived data columns depending on the recursive feature (e.g. a heat flow computed from ‘T’) are recomputed in every step from their expressions. Expressions inside the model are recomputed anyway, since they are part of the keras model.

  • The rollout is a keras RNN around the (trained) step model. It is differentiable, so it can also be used to train a single step model on the multi step error (physXAI.training.recursive).

The resulting errors over the horizon (RMSE, MAE and bias per step) show how the error of the model grows in an MPC, which the single step error does not.
