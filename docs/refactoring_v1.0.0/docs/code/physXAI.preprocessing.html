physXAI.preprocessing.preprocessing module

Preprocessing of time series data for single step and multi step models.

Both preprocessings share one pipeline:

  1. Load the csv file onto a regular time grid of time_step (missing time stamps become rows with missing values instead of silently joining the neighbouring rows).

  2. Apply an optional transform(df) -> df hook (not serialized).

  3. Create derived columns from the naming conventions used by AgentLib-MPC: X_lagN is X shifted by N steps, Change(X) is X(t) - X(t-1). Lags can also be given as lags={'X': 2}, which adds X_lag1 and X_lag2 directly after X to the inputs.

  4. Shift the outputs by shift steps, so row t holds the target predicted from the inputs at t.

  5. Mark rows with missing values as invalid (with ignore_nan=False, missing values between valid rows raise an error).

  6. Split the rows leakage free into training, validation and test data (physXAI.preprocessing.splitting.BlockSplit).

The class names PreprocessingSingleStep and PreprocessingMultiStep and the keys of get_config() are read by AgentLib-MPC and must not change.

class physXAI.preprocessing.preprocessing.PreprocessingMultiStep(inputs=None, output=None, label_width=1, warmup_width=0, overlapping_sequences=True, eval_horizon=None, eval_stride=None, **kwargs)[source]

Bases: PreprocessingData

Preprocessing of multi step (recurrent) models.

A sequence holds warmup_width steps, on which the model warms up starting from a zero state, followed by label_width predicted steps. AgentLib-MPC warms the model up the same way before every MPC step, so training and MPC match. Sequences are only cut out of one split, so training and test sequences never overlap.

Predicting the change (‘Change(T)’) is recommended: the trajectory of T is then the measured start value plus the accumulated changes, and the model is trained on that trajectory.

Parameters:

  • inputs (list[str] | None) – Input features of the model (no lags: the memory of a recurrent model is its state).

  • output (str | list[str] | None) – Output feature(s), e.g. px.Change('T').

  • label_width (int | str) – Number of predicted steps (training horizon), in steps or as time delta string (‘12h’). Choose it longer than the MPC horizon, so the model stays stable over the whole horizon.

  • warmup_width (int | str) – Number of warmup steps, in steps or as time delta string.

  • overlapping_sequences (bool) – If True, training sequences start at every step, else every label_width steps.

  • eval_horizon (int | str | None) – Number of predicted steps of the evaluation (steps or time delta string). Defaults to label_width; a longer horizon shows the stability beyond training.

  • eval_stride (int | str | None) – Distance between two evaluation sequences. Defaults to a quarter of the horizon.

  • **kwargs – See PreprocessingData.

physXAI.preprocessing.splitting module

Leakage free splitting of time series into training, validation and test data.

Rows of a time series are strongly autocorrelated and multi step windows span many rows. Splitting single rows (or overlapping windows) randomly therefore leaks information from the training into the test data. BlockSplit instead assigns contiguous blocks of the time series to the splits (blocked holdout, see Bergmeir et al. 2018 and Cerqueira et al. 2020):

  • Stratified: val and test blocks are drawn from equally sized strata of the time axis, so every split covers the whole period (e.g. all seasons), which a purely random draw does not guarantee.

  • Embargo: gap_steps rows at every boundary between two splits are not used at all (purging, López de Prado 2018), removing the autocorrelation across the boundary.

  • Windows are later only taken from within one split (see physXAI.preprocessing.windows), so no window ever crosses a boundary.

Alternative strategies are 'holdout_end' (chronological: train, val, test), which is more robust for non-stationary data, and 'random_rows' (random rows, only to compare with, single step only).

physXAI.preprocessing.training_data module

Containers for training data.

TrainingData holds the whole preprocessed time series as one NumPy array together with a split label and a validity flag per row. Single step samples and multi step windows of any length are views on that array, so the same data serves the single step training as well as the multi step evaluation. Only NumPy objects are stored: the container can be saved and loaded without pickle (save / load), tf.data pipelines are built by the models when they are fitted.

class physXAI.preprocessing.training_data.TrainingDataMultiStep(series, warmup_width, label_width, stride=1, eval_horizon=None, eval_stride=None)[source]

Bases: TrainingDataGeneric

Sequences of a run, as used by recurrent (multi step) models.

A sequence starts warmup_width steps before the prediction: the model starts from a zero state and warms up on the measured past, as it does in an MPC. Only the following label_width steps are predicted (the warmup is not part of the loss). The sequences are views on the time series (series), so evaluation sequences can be longer than the training sequences (eval_horizon).

For an output ‘Change(T)’ the model predicts the change of T. Its trajectory is the measured start value T(t0) plus the accumulated changes; the y_* attributes hold this trajectory, the targets of the outputs themselves are available via targets(split).

  • warmup_width (int) – Number of warmup steps.

  • label_width (int) – Number of predicted steps (training horizon).

  • stride (int) – Distance between two training sequences.

  • eval_horizon (int | None) – Number of predicted steps of the evaluation. Defaults to label_width.

  • eval_stride (int | None) – Distance between two evaluation sequences. Defaults to stride.

physXAI.preprocessing.windows module

Cutting windows out of a split time series.

A window of length L starting at row s covers the rows s, …, s + L - 1. It is only taken if all of these rows are valid (no missing values) and belong to the same split, so windows never cross a split boundary or a gap in the data.
